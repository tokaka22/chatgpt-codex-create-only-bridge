# ChatGPT 网页 → Codex：只增不改的文档桥

[English](README.md) · [安装步骤](docs/INSTALL.md) · [权限边界](SECURITY.md) · [上游来源](UPSTREAM.md)

让 ChatGPT 网页通过本机或远程机器上的 Codex 读取已登记项目，并把完整文档保存为新版本。网页负责思考、内容与中文风格，Codex 负责读取资料、保存、生成网页和核验。

**核心规则：已有文件保持只读；只能创建新的文件和目录。** 刚发布的文件也不能原地修改，修订需要发布另一套新版本。

本仓库公开的是我们新增的发布器、原生运行守卫、MCP 协议适配层、配置生成器、测试和上游补丁。基础项目来自 MIT 开源的 `menaje/codex-mcp-bridge-for-chatgpt`，保留其上游署名。本项目不是 OpenAI 官方产品，也不包含任何人的账号、隧道凭据或研究资料。

## 工作流程

ChatGPT 网页通过独立连接访问桥接服务；桥根据已登记项目创建新的 Agent 和后台 Job。普通 Codex 命令运行于只读沙箱，审批策略为 never。唯一写入出口是操作者提供的 `publish_document` 函数：它自动创建“文档名称 + UUID”目录，只以独占方式创建新文件。

模型无法通过这个函数选择任意输出根、修改旧文件、删除文件、执行 shell 或访问网络。发布完成后，网页继续查询原 Job，核对真实文件、完整发布回执及章节导航，再向用户交付路径。

需要保留网页语言风格时，先由网页写出正文，再把原文完整交给 Codex 保存。已有完整稿可以凭来源路径和 SHA256 原样复制。

## 使用示例

连接好自己的 ChatGPT 网页后可以说：

> 请基于项目最新资料，用我们确认的中文风格写完整份文档，通过 Codex 保存完整 Markdown 和独立 HTML，自动检查正文、章节与导航。已有文件不能修改、删除或覆盖，修订一律另建新版本。实际完成后给我新目录和验证结果。

修订时可以说：

> 读取上一版，把第三章解释得更具体，发布完整的新版本，上一版全部保留。

日常只读检查不需要逐次 shell 批准，创建新文件走受控函数。ChatGPT 网页连接器是否提示确认，由使用者自己的账号与连接权限设置决定；本仓库不会代改网页权限。

## 安装与限制

这是面向自部署使用者的 v0.1 工具包。需要 Node.js 22+、Python 3.11+、Git、已测试的 Codex CLI 0.153.3，以及自己的 Codex 登录状态。参考部署在 macOS 上完成端到端验收；操作系统沙箱和 ChatGPT 自定义连接能力需要实际满足条件。详见[安装说明](docs/INSTALL.md)。

发布器默认每次最多 32 个 UTF-8 文本文件、合计 4 MiB，支持 Markdown、HTML、TXT、CSS、JSON、CSV、TSV。每次成功发布都会创建新的 UUID 目录，不会覆盖旧版，也没有“自动重复请求沿用同一目录”的保证。失败应先查询原 Job，避免重复提交。

桥接核心、协议适配层、隧道应分别运行。独立重连隧道不应重启核心或取消后台 Job；机器仍需要保持开机联网。配置生成器只写全新的私有运行目录，不会改动已有服务、项目或全局 Codex 设置。

## 测试与许可

包含发布器 22 项、运行守卫 36 项、协议适配层 26 项以及配置生成器测试。单元测试不调用模型，不建立隧道。参考环境另外完成两次九章完整文档的真实网页发布，全程零审批，并通过长任务与独立隧道重连检查；这些是历史验收结果，不等于所有环境均自动兼容。
